# 中繼伺服器

兩個瀏覽器互相找到對方用的郵筒。它**只認房間**，遊戲訊息一律原封轉發——不解析、不儲存、不判斷輸贏。權威在房主的瀏覽器裡（見 `docs/game-design.md` 15.4），所以這台機器就算被入侵也拿不到任何可以作弊的東西。

**一個房間就是一個 Durable Object**，用房號當身分。這不只是實作選擇：把房間放在單一行程的記憶體裡，一旦跑起兩台機器，房主連到一台、客人連到另一台就永遠遇不到彼此。那個錯誤在這裡寫不出來。

## 本機

```bash
npm run relay
```

在 `ws://localhost:8787` 聽，健康檢查在 `http://localhost:8787/health`。開發時不設定任何東西就會自動連到這裡。

跑的是 wrangler 的本機 workerd，也就是**跟部署上去一模一樣的程式**，不是模擬品。`src/match/__tests__/relay.test.ts` 的房間規則測試就是打這個。

## 部署

第一次要先讓 wrangler 拿到你的 Cloudflare 帳號授權（會開瀏覽器）：

```bash
npx wrangler login
```

然後：

```bash
npm run relay:deploy
```

網址會是 `https://salient-relay.<你的子網域>.workers.dev`。確認它活著：

```bash
curl https://salient-relay.<你的子網域>.workers.dev/health
```

回 `{"ok":true}` 就成了。

要改名字的話改 `wrangler.toml` 的 `name`。

## 讓遊戲連到部署好的中繼

建置遊戲時給一個環境變數：

```bash
VITE_RELAY_URL=wss://salient-relay.<你的子網域>.workers.dev npm run build
```

Windows 的 PowerShell 要這樣寫：

```powershell
$env:VITE_RELAY_URL='wss://salient-relay.<你的子網域>.workers.dev'; npm run build
```

**注意是 `wss://` 不是 `ws://`。** 遊戲若透過 HTTPS 提供，瀏覽器會把明文 `ws://` 當成混合內容直接擋掉，而且不會有明顯的錯誤訊息——連線只是默默失敗。沒設定這個變數時，程式會依照頁面本身的協定自動選 `ws` 或 `wss`，並假設中繼跟遊戲在同一台主機的 8787 埠。

建置完把 `dist/` 整個資料夾拖到 Cloudflare 的 Workers & Pages（Create → Pages → Upload assets）。**拖資料夾本身，不是裡面的檔案**；它應該顯示 4 個檔案，看到幾百幾千就是拖錯了。

## 把門關上

遊戲有網址之後，就別讓別的網站用你的中繼。改 `wrangler.toml`：

```toml
[vars]
ALLOWED_ORIGINS = "https://你的遊戲.workers.dev"
```

然後重新部署。多個來源用逗號隔開。

用意要講清楚：瀏覽器送出的 `Origin` 是它自己填的、網頁改不了，所以這擋得住**別的網站**把玩家導到你的中繼。但不是瀏覽器的程式想填什麼就填什麼——**這是一道門，不是一堵牆**。

## 面對公開網路的防護

它會被陌生人連上，所以：

| | |
|---|---|
| 單一訊息上限 | 256 KB（快照約幾 KB，超過幾十倍的東西不是遊戲訊息） |
| 每秒訊息上限 | 40 則（可累積 80 則的爆發量）。房主每秒送 5 份快照、客機是人手速度，所以這個上限差很遠——它是用來擋洪水的，不是用來調節遊戲的。超量就丟棄，持續洪水就斷線 |
| 來源限制 | `ALLOWED_ORIGINS`，見上 |
| 空房回收 | 雙方都離開三分鐘後，房間連同 token 一起消失 |

## 這個架構讓哪些東西變成不必要

寫在這裡是因為它們曾經是必要的，刪掉時值得知道為什麼：

- **心跳**：以前要每 30 秒 ping 一次，否則休眠的分頁會讓房間被鬼佔住。現在平台自己認得死掉的 socket
- **大廳逾時**：以前連上而不進房的 socket 要在兩分鐘後踢掉。現在閒置的房間會休眠，不佔記憶體也不計費，沒有東西需要回收
- **關閉時道別**：以前收到 SIGTERM 要先送 going away，否則重新部署會讓雙方卡在死掉的連線上。現在沒有會被取代的行程
- **同時房間數上限**：以前是 200。現在做不到，因為沒有一個地方看得到全部

## 還沒做的

- **`/health` 不再報告房間數與連線數**：每間房都是獨立實例，誰也不認識誰。要統計就得另外做一個彙總的實例，為了一個數字不值得
- **房號碰撞沒有真的檢查**：開新房時隨機挑一個房號，若正好撞上別人的活房間，會被回「房間已滿」而不是自動換一個。32^6 約十億種組合，實務上不會遇到——但它是「不會遇到」，不是「不可能」
- **沒有身分**：房號加 token 就是全部的憑證，沒有帳號、沒有防止同一個人開一百間房
